# BOT-001 E2A. Надёжность локальной основы

- **Дата** — 20 ноября 2026 года
- **Задание** — [E2A и E3](../TASKS/BOT-001_E2A_E3.md)
- **Ветка** — `main`, исходный коммит ревью `41de18b`

Ключ inbox использовал идентификатор сообщения для всех классов. Из-за этого при совпадении идентификаторов событие остановки, подключения менеджера или закрытия отбрасывалось. Миграция 002 сохраняет номера очереди, признак обработки и состояния, вводит отдельные классы и стабильный идентификатор события. Если повтор ключа ссылается на другое сообщение, сервис возвращает ошибку конфликта. Ранее отброшенные события можно восстановить только повторной доставкой из источника.

Исключение для одной SQL-миграции заменено правилом для трёхзначных имён файлов в каталоге миграций. SQL-выгрузки вне этого каталога, дампы и локальные SQLite остаются исключёнными.

На переносимом Python 3.12.10 прошли десять тестов `unittest` с добавлением корня репозитория в `sys.path`. Проверены схема SQLite через PRAGMA, обновление v1 и чистая база, контрольные события, дубли и конфликт, параллельность, изоляция, перезапуск между записью и обработкой, откат на ошибке SQLite, HTTP 200/404 и 503 для readiness при отказе хранилища. CI проверяет результат первого и повторного CLI replay.

Проверка readiness относится к локальному хранилищу. Актуальность сессии, связанные метаданные и отмена исходящих действий относятся к E3.
