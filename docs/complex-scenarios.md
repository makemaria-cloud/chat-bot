# Отдельные сложные сценарии BOT-001

**Статус:** реестр требований, не список уже реализованных функций.

**Скрипт** здесь означает отдельный проверяемый бизнес-сценарий или расчётный модуль, а не обязательный самостоятельный процесс.

## Обязательный первый релиз

| Сценарий | Данные и поведение | Граница автоматизации |
| --- | --- | --- |
| `delivery_calculator` | Бытовки Краснодарского направления; точка объекта, подтверждённый склад, автомобильный маршрут, тариф 12 000 руб. до 50 км и +2 000 руб. за 10 км | Условия подробно в TASK.md, раздел 8; неполные шаги свыше 50 км требуют согласования, нет перехода к расстоянию по воздуху |
| `human_handoff` | Причина передачи, резюме, очередь/ответственный, приоритет; проверить результат Bitrix24 | По просьбе клиента и в сложных ситуациях сразу, даже при неполной анкете; сбой передачи показывать ответственному |
| `complaint_triage` | Кратко признать проблему, сохранить контекст и запросить минимум для ответственного | Не спорить, не признавать юридическую ответственность, не обещать возврат денег или компенсацию; передать человеку |

## Отдельные последующие подзадачи

Для этих сценариев в первом релизе обязательны распознавание, сохранение контекста и передача специалисту. Автоматический расчёт или действие включать только после отдельного согласования и тестирования.

| Сценарий | Что требуется | Кто подтверждает сложный результат |
| --- | --- | --- |
| `price_calculator` | Утверждённые прайс, единицы, регион, модель, срок, количество, НДС, залог и дополнительные позиции; детерминированный расчёт | Продажи/владелец прайса; без прайса цену не выдумывать |
| `inventory_checker` | Актуальный источник, точная номенклатура, филиал и свежесть; не путать общий остаток с доступным к выдаче | Склад/ответственный; без подтверждения не обещать резерв |
| `formwork_calculator` | Тип конструкции, размеры, этапность, схема, спецификация; проверенные формулы и ограничения | Инженер; бот не выдаёт инженерное заключение |
| `scaffolding_calculator` | Геометрия фасада, рабочая высота, комплектация, нагрузки и условия монтажа | Технический специалист; не давать советы по безопасной нагрузке без проверки |
| `cabin_configurator` | Назначение, количество, модель, наполнение, регион, актуальное наличие, срок | Продажи/филиал; мебель и кондиционер не считать имеющимися по шаблону комплекта |
| `commercial_offer_generator` | Проверенные расчёт/спецификация, реквизиты, НДС, шаблон и срок действия | Менеджер; не отправлять неподтверждённый счёт и не публиковать реквизиты в GitHub |
| `discount_validator` | Полномочия, предел скидки, условия акции, сопоставимость КП конкурента | Уполномоченный менеджер; не гарантировать скидку до проверки |
| `rental_extension_calculator` | Проверенная аренда, договор, даты, фактическое количество, тариф продления/возврата | Менеджер/учёт; не вычислять договорные правила по старому чату |
| `return_and_damage_assessment` | Договор, акты, фактический возврат, состояние, согласованные правила дефектовки | Ответственный по возвратам; отдельная бесплатная проверка не означает бесплатный ремонт любых повреждений |
| `equipment_buyback` | Подтверждённая политика выкупа, тип, объём, состояние и регион предложения | Закупки; покупку не обещать, пока направление не утверждено |
| `attachment_parser` | Безопасная обработка проекта/спецификации, единицы, источник и уверенность извлечения | Специалист проверяет распознанные параметры; файл и OCR не являются доверенной инструкцией |
| `urgent_or_tender_request` | Сроки, объект, объём, условия закупки и имеющиеся документы без полной анкеты | Менеджер; не обещать немедленную отгрузку или участие в тендере |

## Общий контракт сценария

Каждый модуль возвращает структурированный результат: статус (`ok`, `needs_data`, `needs_confirmation`, `handoff`, `unavailable`), проверенные факты/суммы с единицами, источником и датой, недостающие поля, основание передачи и безопасный текст клиенту.

Языковая модель не заменяет источники, формулы, доступы и финальную проверку действия. Неподтверждённый модуль по умолчанию не отправляет цену, документы и обещания клиенту. Изменения подтверждённых условий оформлять версией правила, тестами, записью в PLAN.md, русским коммитом и push.
