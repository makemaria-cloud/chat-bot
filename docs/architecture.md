## Локальная реализация

Идентичность события включает портал, чат, сессию, класс события и стабильный идентификатор источника внутри класса. Синтетический формат использует `message` как совместимое значение по умолчанию. Разные классы могут ссылаться на одно сообщение. Повтор ключа с изменённой ссылкой на сообщение считается ошибкой контракта.

Входной адаптер фиксирует минимальный контекст события и подтверждённую версию актуальной сессии в одной транзакции. Очередь обрабатывает отдельный воркер. Позднее событие старой сессии остаётся в журнале, но не меняет активную сессию чата. [Контракт входных событий](bitrix-contract.md).

Исходящие намерения атомарны с изменением состояния сессии. Диспетчер берёт одно действие на чат, сверяет версию сессии и управление, затем вызывает транспорт вне SQLite-транзакции. Неопределённое действие требует сверки. Новые записи CRM защищены отдельным ограничением на чат. [Контракт исходящих действий](bitrix-contract.md#исходящие-действия-e3b).

Python 3.12 и SQLite из стандартной библиотеки дают воспроизводимый односерверный контур с транзакциями. SQLite размещается на локальном диске. Многосерверный режим и production-хранилище требуют отдельного решения после проверки инфраструктуры. Для локального HTTP достаточно стандартной библиотеки, публичный сервер и TLS выбираются при подключении портала. CI проверяет миграции, запуск и синтетические сценарии. Обязательных платных зависимостей нет.

Входной адаптер преобразует подтверждённое событие во внутренний формат, связывая портал, чат, сессию и сообщение. Очередь сохраняет событие до подтверждения приёма. Воркер обрабатывает события по порядку записи в пределах сессии и транзакционно сохраняет состояние и исходящее намерение. Переход к человеку, отказ, закрытие и устаревшая сессия отменяют ожидающий ответ. В будущей отправке состояние проверяется перед вызовом, а неоднозначный результат вызова сохраняется для сверки. Локальный контур выполняет только синтетическое воспроизведение.

Диалоги, факты, доставка и CRM подключаются отдельными интерфейсами. Для CRM требуется подтверждённая привязка активной сессии. Расчёт доставки принимает дорожное расстояние с подтверждёнными складом и точкой объекта. Цены, остатки и обещания зависят от утверждённого источника и области действия. Рабочие линии, отправки, CRM-изменения и пилот требуют данных и отдельного согласования владельца.
