# BOT-001 E3C: восстановление отменённого CRM-обновления

**Основание:** R3 из [ревью коммита 048df00](../REPORTS/Review_BOT-001_E3C.md).

## Объём

Исправить один оставшийся путь зависания проекции: CRM-план с актуальными полями отменён из-за следующего обычного сообщения без новых CRM-полей, а `crm-bind` не возобновляет его. Сохранить принятые исправления первоначальных R1/R2; не переписывать handoff и не подключать production.

Проверить взаимодействие `schedule_crm`, проверки версий, `finish`, `bind_crm` и уникальности outbox. Отмена конкретной устаревшей попытки не должна делать желаемые поля недоступными для дальнейшей синхронизации.

Допустим автоматический безопасный переход при достоверном отсутствии отправки или явная операция восстановления, но переход должен быть работающим и документированным. Подтверждение привязки не должно скрыто оставлять отменённое обновление без возможности продолжить.

## Приёмочные проверки

- Подтверждённая CRM-привязка, `Plan(crm_fields={quantity: 2})`, затем `Plan(reply=...)` без CRM-полей: последнее допустимое значение попадает в CRM после разрешённого восстановления, без второго создания карточки.
- То же с пустым `Plan()` и с сообщением, для которого планировщик не возвращает нового действия.
- После отмены перезапустить процесс; переподтверждение привязки или документированное восстановление действительно приводит к обновлению, не только возвращает `True`.
- Повторные и конкурентные команды восстановления дают не более одного нового допустимого действия, без `IntegrityError` из-за повторного dedup-ключа.
- За время ожидания пришли ещё новые CRM-поля: отправляется последняя разрешённая проекция, не прежние значения.
- Менеджер, `stop`, закрытие, другая сессия/маршрут не обходятся перепланированием.
- `in_flight`/`uncertain` не считаются отменённой безопасной попыткой: слепого повтора нет.
- Миграции, существующие 40 тестов, dry-run и CI продолжают проходить; при изменении схемы добавить новую миграцию, не менять применённые.

## Сдача

Обновить отчёт E3C с отдельным разделом R3, контракт/README при изменении процедур и `PLAN.md`. Зафиксировать команды и фактические результаты. Сделать отдельный коммит на русском языке и `git push origin main`; сообщить hash и результат CI. До повторного ревью локальный E3B не отмечать принятым.
